# 교회·교육 사역용 HTML 작업 기준

## 1. 먼저 할 일
1. 요청이 어떤 종류인지 정한다: 행사 큐시트 → `templates/cue-sheet`, 교사 묵상 → `templates/devotional`, 그 밖의 것 → 가장 가까운 틀을 복사해 시작.
2. 틀이 있으면 **코드를 새로 짜지 말고 틀을 복사한 뒤 `data/` 폴더의 내용 파일만 채운다.** 틀의 기능을 바꿔야 할 때만 코드를 고치고, 그 변경을 틀에도 반영할지 사용자에게 묻는다.
3. 결과물은 `projects/연도-행사이름/` 폴더에 둔다 (예: `projects/2026-back-festival/`).

## 2. 내용과 틀의 분리
- 내용은 사용자가 엑셀·구글 시트에서 고칠 수 있는 **CSV**(첫 줄은 한글 제목)와 짧은 `event.json`에 둔다.
- 사용자가 표를 붙여 넣거나 사진으로 주면 CSV로 옮긴다. 쉼표가 들어간 칸은 큰따옴표로 감싼다.
- 화면에 보이는 모든 글자는 내용 파일에서 오게 하고, 코드 안에 행사 내용을 적지 않는다.

## 3. 디자인 기준
- 기본 색은 BACK 큐시트의 진녹색·라임. 색은 반드시 `theme.css`의 6개 변수(`--brand --accent --bg --surface --ink --muted`)로만 쓰고, 다른 CSS에는 색 코드를 직접 적지 않는다. 사용자가 색 변경을 원하면 이 6개만 바꾼다.
- 글꼴: Pretendard(jsDelivr) → 시스템 한글 글꼴 순.
- 휴대폰 우선: 최대 폭 560px, 버튼과 체크 칸은 손가락으로 누르기 좋게 크게(최소 44px), 아이폰 노치 영역(safe-area) 처리, 다크 모드 지원.
- 큰 숫자(시각·타이머)는 굵게, 고정폭 숫자(`font-variant-numeric: tabular-nums`).
- 움직임은 최소화하고, 사용자의 ‘동작 줄이기’ 설정을 존중한다.

## 4. 자주 쓰는 부품
구현은 `references/components.md`를 본다.
- 한국 시간 시계 (기기 시간대와 상관없이 KST)
- 예정 시작·종료까지 남은 시간, 진행 막대
- 보조 타이머 (소리 없이 화면 깜빡임)
- 화면 켜짐 유지 (Wake Lock, 지원 안 되면 안내 문구)
- 체크리스트 (이 기기 저장, ‘출발 전 챙기기 / 철수 때 회수’ 두 탭)

## 5. 문구 원칙
- 존댓말, 짧은 문장. 버튼은 하는 일을 그대로 쓴다 (“다음 순서”, “체크 모두 지우기”).
- 오류 문구는 무엇이 잘못됐고 어떻게 고치는지 말한다.
- 용어 통일: 순서, 큐시트, 담당, 메모, 본행사.
- 교단·교회 용어와 신학적 표현은 사용자의 편집 기준을 따른다. 성경 본문은 사용자가 준 번역을 그대로 쓴다.

## 6. 배포 (GitHub Pages)
- 저장소: GitHub 계정 `choo6255`의 `church-html-kit`. Pages는 main 브랜치 루트에서 배포.
- 주소 형식: `https://choo6255.github.io/church-html-kit/projects/폴더이름/`
- 커밋 메시지는 한국어로 짧게 (예: “BACK 페스티벌 큐시트 추가”).
- 배포 전 점검: ① 휴대폰 폭(390px)에서 화면 확인 ② 다크 모드 확인 ③ 개인 연락처·주민번호 등 공개되면 안 되는 내용이 없는지 확인 ④ 링크 열어서 data 파일이 제대로 불러와지는지 확인.
- 파일을 더블클릭해서 열면 data 파일을 못 읽는다. 확인은 `python3 -m http.server`로 하거나 Pages 주소로 한다.
